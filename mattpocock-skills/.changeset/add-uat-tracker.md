Add `uat-tracker`, a user-invoked productivity skill for working one owner's share of a client's UAT feedback sheet. A plan session reads the sheet, takes the user's open rows (their owner code, plus unowned rows in their layer), orders them by the sheet's priority column, groups them for investigation, grills, and sets a rewind point; the next session raises one tracker issue per group (`ISSUES.md`); each later session works one group to a fix and writes its rows' status and a one-line response back, handing the fix to `implement` once the cause is known, which builds it under the worklist's rewind point. `scripts/sheet.py` is the sheet's only writer: it gives rows that have no UID the configured prefix and the next number after the largest already there (`ID_148`), lists rows with `rows`, open ones only with `--open`, adds each response newest first as `- 16 Nov, AB - text`, and refuses when a row already links a different issue. Because testers edit the sheet at the same time, every command except `new` reads and writes through the Excel running on the user's machine (`pywin32`), so a change merges with co-authors cell by cell instead of a saved file overwriting theirs or being discarded by OneDrive; the skill is Windows only. A write refuses a different open workbook of the same name and a cloud workbook with AutoSave off, backs the workbook up through Excel, prints every cell it sets, saves, and reads each cell back; `--dry-run` prints the cells and sets none. The project describes its sheet in `docs/agents/uat-tracker.json` (format in `CONFIG-FORMAT.md`), and `new` builds an empty sheet from it, with the UID in column A, frozen, grey and locked against typing by a Custom data validation of `FALSE`, dropdowns from the config, a How to use tab and a Names tab; set up tells the user to move an existing sheet's UID column to A the same way, by hand. The config's `priorities` maps each level to what it means for the project, agreed with the user at set up from generic starting points, since a level follows how much a problem hurts the product rather than its kind; `new` writes the meanings onto the How to use tab and planning flags rows against them; `write --priority` and `--owner` set a row's priority (as a number when it is digits) and owner, refusing any value the config does not list, once the user agrees it; `add` writes rows the user agreed after the last row, dated today with their type, and gives them UIDs. Graduate leaves `task-prioritisation`, whose `scripts/graduate.py`, `## Graduate` section and `sheet` config keys are removed: raising issues from a feedback sheet now belongs to `uat-tracker`, and `task-prioritisation` keeps the team's issue table. `ask-matt` routes to `uat-tracker` for a client's testers logging feedback in a spreadsheet. The config's `statuses` gain `built`: a row moves to built once every owner's part is merged and closes only once every part is live where the testers test, and `new` colours built blue and explains it on the How to use tab. Working a group opens by saying, in plain words, what its rows report, before any search, code read, query, issue read or subagent, with the cause in depth only after investigating.
