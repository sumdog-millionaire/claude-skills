Add `task-prioritisation`, a model-invoked productivity skill that builds one local HTML table of every open tracker issue and every issue completed in the last seven days. Status and priority each read three words, coloured red, amber and green, and the columns sort, filter and resize. The user edits priority, owner and the queue on the page and saves one changes file; when they say the review is done, the agent applies it to the tracker and rebuilds the table. `scripts/fetch_issues.py` pulls every issue of a Linear project through Linear's API with the project's `LINEAR_API_KEY`, so no agent copies issue data by hand, and `scripts/build_table.py` chooses what to show. The project declares its tracker project, link prefix, queue label and word maps in `docs/agents/task-prioritisation.json` (format in `CONFIG-FORMAT.md`), and the build stops on any value the maps lack rather than showing it wrongly. `ask-matt` routes to it for choosing what to work on next.
