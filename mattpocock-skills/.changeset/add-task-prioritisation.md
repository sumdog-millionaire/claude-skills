Add `task-prioritisation`, a model-invoked productivity skill that builds one local HTML table of every open tracker issue beside the rows of a stakeholder's feedback sheet that no open issue covers. Status and priority each read three words, coloured red, amber and green, and the columns sort, filter and resize. The user edits priority, owner and the queue on the page and saves one changes file; when they say the review is done, the agent applies issue changes through the tracker and row changes through `scripts/apply_sheet_changes.py`, then rebuilds the table. The project declares its tracker prefix, queue label, word maps and sheet columns in `docs/agents/task-prioritisation.json` (format in `CONFIG-FORMAT.md`), and `scripts/build_table.py` stops on any value the maps lack rather than showing it wrongly. `ask-matt` routes to it for choosing what to work on next with a stakeholder. `scripts/fetch_issues.py` pulls a Linear project's open issues through Linear's API with the project's `LINEAR_API_KEY`, so no agent copies issue data by hand, and the workbook's location comes from the project's tracker guidance.
