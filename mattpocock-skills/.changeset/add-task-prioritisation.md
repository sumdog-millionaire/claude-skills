Add `task-prioritisation`, a model-invoked productivity skill that builds one local HTML table of every open tracker issue and every issue completed in the last seven days. Status and priority each read three words, coloured red, amber and green, and the columns sort, filter and resize. The user edits priority, owner and the queue on the page and saves one changes file; when they say the review is done, the agent applies it to the tracker and rebuilds the table. `scripts/fetch_issues.py` pulls every issue of a Linear project through Linear's API with the project's `LINEAR_API_KEY`, so no agent copies issue data by hand, and `scripts/build_table.py` chooses what to show. The project declares its tracker project, link prefix, queue label and word maps in `docs/agents/task-prioritisation.json` (format in `CONFIG-FORMAT.md`), and the build stops on any value the maps lack rather than showing it wrongly. `scripts/graduate.py` turns every open feedback row with an owner and no linked issue into an issue assigned to that owner, skipping unassigned rows, groups rows the agent and user agree share a theme into one issue (`--groups`), and writes each issue's address back into its rows, after a dry run the user approves; whether a row is a data problem or a fix is left to the issue's investigation; `scripts/linear.py` holds the API call both scripts share. On every run the skill checks that the project's `CLAUDE.md` names the queue label, and proposes the section in `QUEUED-WORK.md` when it does not. `ask-matt` routes to it for choosing what to work on next.
