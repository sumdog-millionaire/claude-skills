`tdd` now runs its loop with holdouts, tests the builder never sees, because a builder that can read its tests builds to pass them. Two plugin agents carry the loop: `tester` writes a slice's tests from the spec and the agreed seams before the code exists, beside a `seams.md` that tells the builder how the tests call the code and nothing about what they check, and later promotes them into the project's tests; `validator` runs them, uses the app or code the way it is really used, and reports failures as missed behaviour without quoting a test. The holdouts live in `holdouts/<ticket>/` inside the repository's git folder, and a `PreToolUse` hook (`tdd/scripts/guard_holdouts.py`) blocks every other agent from them except `seams.md`. The builder may ask for a seam change only when a seam would force unnatural code, and it changes how the tests call the code, never what they check. Three red reports or a disputed test stop the build and go to the user. `implement` and `implement-spec` run the loop, `implement-spec`'s orchestrator launching the tester and validator for its implementers, and both promote the holdouts only after the user confirms the result meets the intent. Holdouts are on by default and a user can opt out per ticket.
